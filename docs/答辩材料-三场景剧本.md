> 用途：答辩演示 + 讲解「置信度驱动混合研判」的技术贡献点。

---

## 一、三场景演示剧本

### 场景 1：快速路径（高置信度，不进沙箱）

**演示动作**：贴一条典型诈骗短信，如「【速运中心】您的包裹已破损，请点击链接办理理赔」。

**预期展示**：
- RAG 检索命中相似案例（高相似度），话术库命中「快递理赔」模式
- 置信度评估显示 **高置信度（≥80%）**
- 路径决策显示 **快速路径，未触发沙箱**
- 秒级返回「诈骗」结论 + 引用相似案例

**讲解点**：「90% 的常见话术，RAG 直接秒判，不浪费沙箱资源。」

### 场景 2：沙箱触发（低置信度 / 伪装样本）

**演示动作**：贴一个**新注册域名/短链**的「银行 KYC 认证」链接。

**预期展示**：
- RAG 相似度低（新话术/伪装），置信度 **低于阈值**
- 路径决策触发 **沙箱动态分析**
- 沙箱返回行为证据：重定向链、表单字段（银行卡/验证码）、恶意 JS、IOC 命中
- Agent 综合研判 → 「高危钓鱼」，证据链完整

**讲解点**：「拿不准的 10%，自动进沙箱看真实行为，不漏掉精心伪装的威胁。」

### 场景 3：防御闭环（规则兜底，沙箱推翻 RAG）

**演示动作**：贴一个「索要银行卡+验证码」且命中强制规则的样本。

**预期展示**：
- 即使 RAG 给出高置信度，**规则兜底强制进沙箱**
- 沙箱发现真实恶意行为，**推翻 RAG 的误判**
- 展示「防御闭环」：规则兜底 → 沙箱交叉验证 → 纠正结论

**讲解点**：「即使知识库被投毒/干扰，规则兜底 + 沙箱交叉验证仍能守住底线。」

## 二、答辩要点（速记）

### 一句话定位
面向反诈的「RAG + Agent + 沙箱」**置信度驱动混合研判系统**。

### 技术贡献点
不是「又一个检测器」，而是**资源调度策略**：置信度作为两路径的调度器，高置信度走 RAG 快速路径，低置信度走沙箱深度验证，可量化、可解释、可配置。

### 关键数据（消融实验，跑 `npx tsx scripts/ablation.ts`）
| 模式 | 准确率 | 沙箱调用率 | 平均耗时 |
|---|---|---|---|
| RAG-only | ~ | 0% | 快 |
| Sandbox-only | ~ | 100% | 慢 |
| **混合（本系统）** | 接近 Sandbox-only | **~15%** | 接近 RAG-only |

**金句**：「用 ~15% 的沙箱成本，拿到接近全量沙箱的准确率。」

### 架构亮点（对评委）
1. **确定性调度**：置信度是代码算的，不是模型猜的——可解释、可配置（权重/阈值都是常量）
2. **规则兜底**：短链/索要敏感信息 → 强制沙箱，防绕过、防投毒
3. **离线兜底**：内存向量库（B）+ Tier0 沙箱（C），断网也能完整演示
4. **全链路证据**：输入→检索→置信度→沙箱→研判，每个结论可回溯
5. **符合赛制**：前端为主、后端仅接入层、Next.js 全栈、流式 AI

### 可能被问的问题 + 答案
- **Q: 阈值为什么是 0.8/0.55？** A: 权重和阈值都是可配置常量，通过消融实验调出来的，答辩时展示调参过程。
- **Q: 沙箱调用率怎么从 100% 降到 15%？** A: 高置信度样本不进沙箱，只有低置信度/规则命中才进，这是置信度调度的核心价值。
- **Q: RAG 被投毒怎么办？** A: 规则兜底 + 沙箱交叉验证，沙箱行为可推翻 RAG 结论（场景 3 演示）。
